# 🐙 Пълно Ръководство за работа с Git и GitHub (Windows & Linux)

Този документ описва стъпка по стъпка работния процес, настройката на SSH ключове и как да работите ефективно с версия контрол.

---

## 🔑 1. Настройка на SSH Ключ (Authentication)
За да работите с GitHub без да въвеждате парола всеки път, ви трябва SSH ключ.

### Стъпка A: Проверка и Генериране
Отворете терминал (Git Bash за Windows или Terminal за Linux) и изпълнете:

1. **Проверете за съществуващи ключове:**
   ```bash
   ls -al ~/.ssh
   ```
   Ако виждате файлове като `id_ed25519` или `id_rsa`, вече имате ключ. Ако не, продължете.

2. **Генерирайте нов ключ:**
   Ние използваме `ed25519` (най-модерния стандарт).
   ```bash
   ssh-keygen -t ed25519 -C "vashia_email@example.com"
   ```
   - Натиснете **Enter**, за да запазите файла по подразбиране.
   - Натиснете **Enter** два пъти, когато ви пита за "passphrase" (оставете празно за удобство, или въведете парола за extra сигурност).

### Стъпка B: Добавяне на ключа в GitHub
1. Вземете публичния ключ:
   ```bash
   # За Windows (Git Bash):
   cat ~/.ssh/id_ed25519.pub | clip

   # За Linux:
   cat ~/.ssh/id_ed25519.pub
   # (Копирайте изведения текст)
   ```
2. Отворете GitHub -> **Settings** -> **SSH and GPG keys** -> **New SSH key**.
3. Заглавие: (Напр. "My Laptop Windows").
4. Key: Поставете копирания текст.
5. Натиснете **Add SSH key**.

### Стъпка C: Активиране на SSH Agent (За да не пита постоянно)
Ако ключът ви има парола или Windows го забравя:

```bash
# 1. Стартиране на агента във фонов режим
eval "$(ssh-agent -s)"

# 2. Добавяне на ключа към агента
ssh-add ~/.ssh/id_ed25519
```

## 🚀 2. Стартиране на работа (Клониране)

Когато започвате на нова машина:

```bash
# Отидете в папката за проекти
cd Projects

# Клонирайте чрез SSH (препоръчително)
git clone git@github.com:YOUR_USERNAME/Hydroponics_v5.git

# Влезте в папката
cd Hydroponics_v5
```

---

## 🌿 3. Правилният Workflow (Работа с Клонове)

**ЗЛАТНО ПРАВИЛО:** Никога не работете директно в `main` клона!

### 3.1. Започване на задача
Винаги създавайте нов клон за всяка нова задача или фикс.

```bash
# 1. Свалете първо най-новото от сървъра
git checkout main
git pull origin main

# 2. Създайте нов клон (branch) и влезте в него
# Формат: category/short-description
git checkout -b feature/setup-docker
# или
git checkout -b bugfix/fix-simulator-crash
```

### 3.2. Работа и Промени
Правете си промените по кода. Git следи всичко.

---

## 💾 4. Запазване на промените (Commit)

След като сте готови с промените:

1. **Добавяне на файловете (Staging):**
   ```bash
   git add .
   ```
   *(Точката означава "всички промени". Може и конкретен файл: `git add backend/src/index.ts`)*

2. **Създаване на Commit:**
   ```bash
   git commit -m "feat: add docker configuration for rpi"
   ```

### 🤖 Как да накарате AI да напише Commit Message?
Ако не ви се пише описание, попитайте ме (AI):

> **Промпт към мен:**
> "Направи анализ на промените, които направихме досега (`git status` или `diff`), и генерирай кратък и ясен commit message спазвайки Conventional Commits стандарта."

Аз ще анализирам кода и ще предложа нещо като: `feat(docker): add compose file for raspberry pi`.

## ☁️ 5. Качване в GitHub (Push)

Когато сте готови да качите работата си:

```bash
# Качване на текущия клон
git push origin feature/setup-docker
```

*Ако за първи път качвате този клон, Git ще ви подскаже точната команда, която обикновено е:*
`git push --set-upstream origin feature/setup-docker`

---

## ⬇️ 6. Сваляне на промени (Pull)

Ако сте работили от друг компютър или колега е направил промени:

```bash
# Върнете се в главния клон
git checkout main

# Издърпайте промените
git pull origin main
```

---

## 🔄 7. Сливане на промените (Merge)

След като сте качили клон (`push`) и сте тествали всичко:
1. Отворете GitHub репозиторито в браузъра.
2. Ще видите бутон **"Compare & pull request"**.
3. Създайте Pull Request (PR) -> Merge -> Confirm.
4. Изтрийте стария клон (Delete branch).

В локалния терминал почистете:
```bash
git checkout main
git pull origin main
git branch -d feature/setup-docker  # Изтрива локалния клон
```

## �️ 8. Работа с Git GUI (Графичен Интерфейс)

Ако предпочитате да работите с мишка, вместо с терминал.

### 8.0. Поправка на Кирилицата (Encoding Fix)
Ако виждате странни символи (йероглифи) вместо кирилица в Git GUI:
1. Отворете Git GUI.
2. Отидете на **Edit** -> **Options**.
3. Вдясно (Global) и вляво (Repository) намерете **Default File Contents Encoding**.
4. Сменете го на `utf-8`.
5. Натиснете **Save**.

### 8.1. Отваряне
1. Десен бутон върху папката на проекта -> **Git GUI Here**.
2. В горния ляв ъгъл виждате:
   - **Unstaged Changes**: Променени файлове, които още не са готови за commit.
   - **Staged Changes**: Файлове, които ЩЕ влязат в commit-а.

### 8.2. Правене на Commit (Commit)
1. **Преглед:** Кликнете върху файл в "Unstaged", за да видите промените.
2. **Stage:**
   - За да добавите един файл: Кликнете върху иконата на файла вляво от името му.
   - За да добавите ВСИЧКИ: Натиснете бутона **Stage Changed**.
3. **Съобщение:** В полето "Commit Message" напишете описанието (напр. `feat: added git manual`).
4. **Commit:** Натиснете бутона **Commit**.

### 8.3. Качване (Push)
1. Натиснете бутона **Push**.
2. В прозореца изберете:
   - **Source Branch:** Текущият клон (напр. `feature/setup-docker`).
   - **Remote:** `origin`.
3. Натиснете **Push**.

### 8.4. Създаване на нов клон (Branch)
1. Меню **Branch** -> **Create**.
2. **Name:** Въведете името (напр. `bugfix/fix-encoding`).
3. **Starting Revision:** Обикновено `main` или текущия клон.
4. **Create**.

### 8.5. Сваляне на промени (Pull)
Git GUI няма директен бутон "Pull". Най-добре ползвайте:
- Меню **Remote** -> **Fetch from** -> **origin**.
- Меню **Merge** -> **Local Merge** -> Изберете какво да слеете.
*(За Pull операции е по-лесно да ползвате терминала или `Git Desktop`/`VS Code`).*

## ⚠️ Спешни ситуации

**Q: Оплесках нещата, искам да върна всичко както беше в последния commit.**
A: `git reset --hard` (Внимавайте, губите незапазените промени!)

**Q: Работех в `main` без да искам!**
A: Няма проблем. Не commit-вайте. Просто напишете `git checkout -b new-branch-name`. Git автоматично ще пренесе промените ви в новия клон.

**Q: SSH ключът изтече или не работи?**
A: Повторете "Стъпка 1". Генерирайте нов ключ и заменете стария в GitHub настройките. Няма нужда да триете репозиторито.
