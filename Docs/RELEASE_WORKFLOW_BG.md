# Ръководство за Публикуване на "Ceres - OpenHydro"

## 🎯 Какво постигнахме?
Създадохме автоматизирана система за публикуване на проекта. Тя разделя работата на две:
1.  **Работна Среда (`Hydroponics_v5`):** Тук е "кухнята" – целият хаос, експерименти, лични данни и пълна история. Тук работим всеки ден.
2.  **Дистрибуция (`Ceres-OpenHydro`):** В съседна папка имаме чисто копие, което съдържа само готовия, работещ код за публиката. Няма тайни, няма излишни файлове.

---

## 🚀 Как се работи оттук нататък?

### Процедура за Ежедневна Работа
Продължаваш да работиш **само** в `Hydroponics_v5`.
- Пишеш код, оправяш бъгове, добавяш функции.
- Използваш Git както досега.
- Не мислиш за публичното репо.

---

## 📅 Процедура "Публикуване на Версия" (Release Workflow)

### СТЪПКА 1 (ВИНАГИ): Синхронизация
Независимо дали е първи път или стотен, винаги започваме така.
Влизаш в работната папка (`Hydroponics_v5`) и стартираш нашия скрипт:

```bash
# В терминала на Hydroponics_v5
node scripts/publish-ceres.js --run
```

*Какво прави това?*
- Изтрива старата версия в папка `../Ceres-OpenHydro`.
- Копира новата (чиста) версия от текущия ти проект.
- Заменя името в `package.json` на `ceres-openhydro`.

---

### СТЪПКА 2: Изпращане към GitHub

Тук има два варианта. Избери правилния според ситуацията.

#### 🅰️ ВАРИАНТ А: ПЪРВО ПУБЛИКУВАНЕ (First Time Setup)
Изпълнява се **само веднъж**, когато папката `Ceres-OpenHydro` е нова и още няма Git.

```bash
# 1. Отиваш в публичната папка
cd ../Ceres-OpenHydro

# 2. Инициализираш Git (само първия път)
git init

# 3. Добавяш всички файлове
git add .
git commit -m "Initial Release: Ceres 1.0 (Beta)"

# 4. Свързваш с GitHub (само първия път)
# (Вземи точния URL от GitHub, ако е различен)
git branch -M main
git remote add origin https://github.com/shadowmb/ceres-openhydro.git

# 5. Изпращаш
git push -u origin main
```

#### 🅱️ ВАРИАНТ Б: РУТИНЕН ЪПДЕЙТ (Update / Patch)
Изпълнява се всеки път, когато пускаш нова версия (Beta 1.1, 1.2...).

```bash
# 1. Отиваш в публичната папка
cd ../Ceres-OpenHydro

# 2. Проверяваш разликите
git status

# 3. Добавяш всичко (скриптът вече е изчистил излишното)
git add .

# 4. Създаваш версията
git commit -m "Update: v1.1 - Added Demo Data and Fixed Bugs"

# 5. Изпращаш
git push
```

---

## ⚠️ Важни правила

1.  **Никога не пиши код в `Ceres-OpenHydro`!** Всички промени там ще бъдат изтрити при следващата синхронизация. Промените се правят само в оригиналния проект.
2.  **Демо Данни:** В бъдеще трябва да създадем файл с "чисти начални данни" (seeds), за да може новият потребител да има работеща система веднага след инсталация.
3.  **Сигурност:** Скриптът автоматично пази тайните файлове (`.env`, `creds/`), но винаги е добре да хвърлиш едно око на `git status` преди да пуснеш `git push`.
